# リスニング確認 作業指示書

**対象**：Level Trim #2〜#6（選定基準を反転して再構築した版）
**目的**：クロスフェードの継ぎ目でテイク間のキー／テンポが衝突していないかを確認する
**関連**：[review-2026-08-24.md](./review-2026-08-24.md) 指摘3（未解決）／[changelog.md](./changelog.md)

---

## なぜこれが残っているのか

Sunoの2テイクは、**同じプロンプトから生成されていても互いに独立**している。キーもテンポも揃っている保証がない。

`acrossfade` は継ぎ目を滑らかにするが、**重なった区間では2つの音が実際に同時に鳴る**。キーが違えば濁りとして、テンポが違えば拍のにじみとして残る。滑らかにすることと、衝突しないことは別。

これまでの検証（バイト単位のPCM比較）は「**意図したテイクが使われているか**」を確認するもので、**音楽的に成立しているか**は見ていない。だから未解決のまま残っている。

**さらに、選定基準を「密度が高い方」→「静かな方」に反転して全曲を再構築したため、継ぎ目の位置そのものが変わっている。旧版で済ませた確認は無効。**

## 手順

### STEP 1：継ぎ目の位置を特定する

再構築時のセグメント境界がどこか。ローカルの作業記録に残っていればそれを使う。

残っていない場合は、結合スクリプトのログか、以下で当たりをつける：

```bash
# 音量の不連続点を探す（継ぎ目の候補）
ffmpeg -i "04 Thread Pool (combined).wav" -af "astats=metadata=1:reset=1,ametadata=print:key=lavfi.astats.Overall.RMS_level" -f null - 2>&1 | grep -A1 pts_time | head -60
```

**単体採用の曲（Long Poll / Hot Path）は継ぎ目がないのでこのSTEPは不要。** ただし通し聴きはする。

### STEP 2：耳で確認する（これが本番）

**継ぎ目の10秒前から10秒後まで**を、以下の3通りで聴く。

| 聴き方 | 見つかるもの |
|---|---|
| **ヘッドホン・中音量** | キー衝突（濁り・うなり）。低音のうねりが最も分かりやすい |
| **小音量・ながら聴き** | 実使用に近い条件。**ここで気になるなら不合格** |
| **作業しながら通し聴き** | 最終判定。注意が引っ張られる箇所があれば、そこが問題 |

**聴き分けるポイント**

- **キー衝突** → 和音が濁る、「うわーん」というビート（うなり）が出る、気持ち悪さが残る
- **テンポ衝突** → 拍がずれる／もたつく、リズムが二重に聞こえる
- **音量段差** → 継ぎ目で明らかに音量が変わる

**この曲群にとっての合格基準は「作業中に気づかないこと」。** 分析的に聴いて微妙な違和感があっても、ながら聴きで意識に上らなければ合格でよい。逆に、分析的には分からなくても作業中に注意が逸れたら不合格。

### STEP 3：優先順位

| 曲 | 継ぎ目 | 優先度 |
|---|---|---|
| **Thread Pool** | 3回（5秒に延長済み）／4:30と短尺 | **最優先。継ぎ目の密度が最も高い** |
| Backpressure | 2回 | 高 |
| Warm Cache | 1回＋末尾カット | 中。**5:15以降のハミング再発も併せて確認** |
| Long Poll | なし（単体採用） | 低。通し聴きのみ |
| Hot Path | なし（単体採用） | 低。通し聴きのみ |

**Warm Cache は末尾も要確認。** take1の使用終端を5:15に短縮（ハミング開始5:30に対し15秒マージン）＋末尾4秒フェードアウトを追加済み。ハミングが本当に消えているか耳で確認すること。

## 補助ツール（任意）

`tools/crossfade_check.py` — 継ぎ目の前後でキー（クロマ）とテンポを比較し、**聴くべき箇所を絞り込む**。外部ライブラリ不要（ffmpegのみ）。

```bash
python3 tools/crossfade_check.py "04 Thread Pool (combined).wav" --joins 90 150 255 --xfade 5
```

> ⚠️ **このスクリプトはリモート環境にffmpeg/numpyが無く、実行検証できていない。**
> 使う前に、意図的にキーの違う2音を結合したテストファイルで動作を確かめること。
> 動かない・結果が怪しい場合は捨ててよい。**STEP 2 の耳での確認が本体であり、これは補助にすぎない。**

数値上OKでも耳で違和感があれば耳を優先する。逆も同じ。

## 問題が見つかったときの対処

軽いものから順に試す。

### 1. クロスフェードを延ばす（3〜5秒 → 8〜10秒）
最も安価。軽度の衝突なら、重なりを長くして両者を溶かすことで目立たなくなる。
この曲群は `no build-up` / `sustained and unchanging` の設計なので、**長いクロスフェードは音楽的に不自然にならない**。

### 2. 継ぎ目の位置をずらす
静かな区間（パッドだけが鳴っている箇所）に移動する。打楽器が動いている箇所での切り替えが一番ばれやすい。

### 3. その曲は単体テイクにする
Long Poll / Hot Path と同じ扱いにする。**結合は目的ではなく手段**なので、成立しないなら捨ててよい。片方のテイクが通しで使えるならそれが最善。

### 4. Suno で再生成する
Thread Pool は尺も短い（4:30 vs 他7:53〜7:59）ので、**もともと再生成が推奨されている**（review指摘4）。
リリースは審査待ち27〜29営業日を織り込んでも余裕があるため、作り直しは現実的な選択肢。
プロンプトは [prompts.md](./prompts.md) の #4 をそのまま使う。
