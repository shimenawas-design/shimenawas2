# A案 仕様書：シフトうさぎ（介護夜勤 × 目が死んだ白ウサギ）

「後出しジャンケン制作法」のテスト第1弾。**採用・制作中**。

| 項目 | 内容 |
|---|---|
| ターゲット界隈 | 介護施設の夜勤スタッフ（特養・老健・グループホーム） |
| 絵柄 | ゆるかわ系だが目が完全に死んでいる3頭身の白ウサギ |
| 検証する変数 | 「可愛い絵柄で毒を吐く」ギャップは売れるか（本命枠） |

---

## 1. キャラクター設定（固定・変更禁止）

3頭身の白ウサギ／丸い体／短い手足／少し垂れた長い耳。

- **目**：黒い点目。ハイライト・光沢・輝きを一切入れない。常に半目。目の下にクマ
- **口**：小さな横一本線
- **輪郭線**：黒ではなく濃いグレーの細線、均一な太さ
- **服**：くすんだミントグリーンの介護用半袖ポロシャツ、胸に白い名札（文字なし）、紺のチノパン
- **配色**：低彩度パステル、フラット塗り、グラデーションなし、テクスチャなし

**どんなに元気なセリフでも目は死んだまま** ── このギャップが商品の核。
30「笑顔だけは死んでない」が看板コマで、口だけ満面の笑みなのに目は完全に死んでいる、
という最大コントラストを担う。

## 2. 制作方針（毒の矛先の設計）

笑う対象を **「自分自身」と「業務・シフト・制度」に限定** する。

毒の矛先を利用者・入居者に向けると界隈から嫌われ、審査リスクも上がる。
これは倫理面の配慮ではなく **資産価値の維持のための設計判断**。

お看取り・急変ネタは界隈のリアルさでは最上位だが、意図的に全除外。

## 3. 40個の設計図

**単一の真実は `data/stamps_40.json`。** セリフ・改行位置・ACTION・EXPRESSION・タグを
すべてここに持つ。人間が読む用の出力は `prompts/` 以下に生成する。

| カテゴリ | 個数 | 番号 |
|---|---|---|
| 挨拶・業務連絡（実用枠） | 10 | 01〜10 |
| 夜勤特化 | 8 | 11〜18 |
| 業務あるある | 8 | 19〜26 |
| 愚痴・自虐 | 8 | 27〜34 |
| 労い・連帯 | 6 | 35〜40 |

実用枠を10個先頭に置いているのは、界隈語だけだと日常のサジェストに出ず使用頻度が落ちて
口コミが生まれないため。

## 4. プロンプト設計

BASE / NEGATIVE は40枚すべてで一字一句同じ。差し替えるのは `{{ACTION}}` と
`{{EXPRESSION}}` の2箇所だけ。**これがキャラのブレを構造的に防ぐ唯一の方法。**

`scripts/build_prompts.py` が唯一の正で、`prompts/_base.md` にコピペ用が生成される。
手で `prompts/` を編集しない（再生成で上書きされる）。

生成側の「上部30%を空ける」は**安全マージン**で、耳や挙げた手が文字ゾーンに侵入するのを
防ぐためのもの。実際のテキストゾーン（上端0〜110px）は `compose.py` が
キャラのバウンディングボックスを基準に再配置して確定させる。

## 5. テキスト載せ工程

| 項目 | 値 |
|---|---|
| スタンプ画像 | 370 × 320 px / PNG / 背景透過 |
| メイン画像 | 240 × 240 px（#30から生成） |
| タブ画像 | 96 × 74 px（#30の顔まわり、文字なし） |
| テキスト配置ゾーン | 上端から 0〜110 px（上部約35%）／中央揃え |
| **フォントサイズ** | **36 px 固定**（全40個で統一。自動縮小はしない） |
| **改行ルール** | **1行9文字以内。超える場合は2行**（行送り42px） |
| フォント | Zen Maru Gothic Bold（`fonts/ZenMaruGothic-Bold.ttf` / SIL OFL） |
| 文字色 | 濃いグレー `#4A4A4A` |
| フチ | 白 5 px |
| 余白 | 上下左右 10 px 以上（LINE規定） |
| キャラ配置 | 下寄せ（下マージン10px）、高さ200px・幅350pxに正規化 |

**フォントサイズを固定した理由**：文字数に合わせて自動縮小すると 44px〜24px までバラつき、
40個並んだショップページで統一感が崩れる。サイズを固定し、長いセリフは2行にする方が揃う。

**改行位置は自動折り返しに任せず、意味の切れ目で明示指定する。**
`data/stamps_40.json` の `lines` に全40個分を持っており、
`prompts/texts_40.md` で1行9文字以内に収まっているか検証できる（現在の超過：0件）。

2行になるのは 06 / 20 / 24 / 25 / 27 / 30 / 31 / 33 の8個のみ。

## 6. 仕上げワークフロー

```bash
# 1. Gemini の生画像を raw/ に置く（先頭2桁が番号：01_xxx.png 〜 40_xxx.png）
python compose.py                 # 一括処理
python compose.py --thresh 230    # 背景が薄グレーで抜けきらない場合
python compose.py --only 30       # 1枚だけ確認
python compose.py --placeholder   # 生画像なしでレイアウト検証
```

出力は `out/` に `01.png`〜`40.png` / `main.png` / `tab.png` /
`_contactsheet.png`（全40個を並べた統一感チェック用）。

処理内容：背景透過（縁と地続きの白のみをフラッドフィルで抜くため、白いキャラ本体に穴が
空かない）→ キャラのバウンディングボックスを基準に高さ200pxへ正規化 → 下寄せ配置 →
テキスト載せ。

**`compose.py` はローカル環境（Windows）側にあり動作検証済み。**
このリポジトリには未収録。必要になったらアップロードして取り込む。

### コンタクトシートで確認すべき点

正規化を高さ基準で行うため、**横に広いポーズが幅350pxを超えて縮み、他より小さく見える**
可能性がある。該当しやすいのは以下。

- 04 明けました（床に溶けて広がる）
- 20 コール2つ同時は無理（両腕を左右に伸ばす）
- 34 数えるのやめました（腕を広げる）

`_contactsheet.png` で他の37個と並べ、キャラの体格が揃っているか確認する。
