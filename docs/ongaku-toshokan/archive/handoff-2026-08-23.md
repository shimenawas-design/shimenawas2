### 音源の来歴と、未解決の技術的論点

- 音源は **MP4からの変換によるMP3**
- **1ファイル30MB超**（320kbpsなら約12.5分に相当。長尺のアンビエントとして辻褄は合う）

**指摘した点**：MP4の音声は通常AAC（既に非可逆）なので、MP3化は**非可逆→非可逆の再エンコード**であり音質は劣化する。「MP4からの変換なので音質が変わらない」という前提は正しくない。

**ユーザーの判断**：音源の変換は不要。現状のMP3で提出する。

**→ ただし品質とは別に、規格適合が未確認のまま残っている（下記）。**

## 🔴 最優先タスク：MP3のスペック確認

RouteNote は **MP3 (320kbps / 44.1kHz)** か **FLAC (44.1kHz)** しか受け付けない。
MP4由来だと元が128〜256kbpsのことがあり、その場合は**音質の話ではなく規格不適合で弾かれる**。審査サイクルを1回無駄にするので、提出前に必ず確認すること。

前セッションでは30MB超でファイルを渡せず未確認。**ローカルなら直接調べられる。**

```bash
for f in *.mp3; do
  echo "=== $f"
  ffprobe -v error \
    -show_entries stream=codec_name,bit_rate,sample_rate,channels \
    -show_entries format=duration,size \
    -of default=noprint_wrappers=1 "$f"
done
```

**合格条件**：`sample_rate=44100` かつ `bit_rate` が 320000 前後。

**不合格だった場合**：MP3から再エンコードしても品質は戻らない。**Sunoの元WAV（または元のMP4）に遡って変換し直すのが唯一の正解。**

```bash
# 元WAVがある場合
ffmpeg -i "01 Rainy Kyoto.wav" -ar 44100 -map_metadata -1 "01 Rainy Kyoto.flac"

# 元MP4しかない場合（AAC→MP3の劣化は避けられないが、規格は満たせる）
ffmpeg -i "01 Rainy Kyoto.mp4" -vn -ar 44100 -c:a libmp3lame -b:a 320k -map_metadata -1 "01 Rainy Kyoto.mp3"
```

`-map_metadata -1` は **"made with suno" の埋め込みメタデータ削除のため必須**。

## アルバムメタデータ（ドラフト・ユーザー未承認）

トラック名は**季節（桜→新緑→夏→秋→雪）と時間帯（朝・雨・深夜）で京都を一巡する構成**になっている。それを前面に出す方針。

| 項目 | 案 |
|---|---|
| **アルバム名** | `A Year in Kyoto` |
| ジャンル | Ambient（副ジャンル欄があれば New Age） |

**アルバム名の根拠**：10曲が年間を巡る構成であることが一目で伝わり、「曲の寄せ集め」ではなく「作品」として読める。検索性を優先するなら `Kyoto Ambience` だが、汎用的すぎて埋もれる。

**英語説明文（案）**
```
Ten ambient pieces tracing a year in Kyoto — rain on temple stone, morning light, summer shade, and snow.
Instrumental and unhurried: made for reading, working, and winding down.
```
※ 審査担当は日本語を読めない前提で英語で書く。

### 細かい指摘（任意対応）
- `Fresh Green` は新緑の直訳で英語としてやや据わりが悪い。`Early Summer Green` などが自然だが、意味は通るので必須ではない
- 10曲中5曲に "Kyoto" が入っている。テーマとして自然な範囲だが、**Spotifyのスパム指標に「メタデータのSEO操作」がある**ので、これ以上増やさないこと

## AI音楽を取り巻く2026年の環境（2026-08-23 調査）

**リリース頻度の設計に直結するので必読。**

### Deezer（最も厳しい）
- 完全AI生成トラックを検出し、**タグ付けのうえアルゴリズム推薦とエディトリアルの両方から除外**。2025年だけで1,300万曲をタグ付け
- 完全AI生成曲のストリームの**最大85%が不正と判定され収益化停止**（2026年1月）
- **2026年1月から検出技術を他社にライセンス販売中** ← 逃げ場が減っていく
- 2026年7月時点で**1日約90,000曲**が入稿され、ピーク日には**全入稿の50%超**

### Spotify
- スパムフィルタが止めるのは「**大量アップロード、重複、メタデータのSEO操作、不自然に短いトラック**」
- 入稿の**約39%が自動フラグ**、直近12ヶ月で**7,500万曲を削除**
- ただし「**責任あるAI利用を罰したりダウンランクさせるものではない**」と明言。問題視しているのはAIであること自体ではなく**挙動と意図**

### RouteNote
- 数量上限は非公表だが、**スパム的に見える大量AI入稿は拒否**。高頻度入稿は手動レビュー対象
- **使用したAIツールへのリンク提出を要求**する

**含意**：「Spotifyを除外すれば高頻度リリースできる」は成立しない。10曲入りアルバム1本は「大量アップロード」ではないので今回は問題ないが、**この名義で多作路線を続けるなら頻度設計が必要。**
