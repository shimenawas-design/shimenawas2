# Gemini 画像一括ダウンローダー（Chrome拡張機能）

Google Gemini（https://gemini.google.com/ ）のチャット画面に表示されている
生成画像を、ワンクリックでまとめてローカルに保存できる Chrome 拡張機能（Manifest V3）です。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `manifest.json` | 拡張機能の設定ファイル（権限・対象サイト・各スクリプトの登録など） |
| `content.js` | Geminiのページに埋め込まれ、DOMから生成画像のURLを抽出するスクリプト |
| `background.js` | ポップアップと content.js の橋渡しをしつつ、実際のダウンロード処理（chrome.downloads API）を行うサービスワーカー |
| `popup.html` / `popup.css` / `popup.js` | 拡張機能アイコンをクリックしたときに表示するUIとその動作 |
| `icons/` | 拡張機能のアイコン画像（16px / 48px / 128px） |
| `docs/INSTALL_README.txt` | 非技術者向けのインストール手順書（配布用ZIPに同梱される） |
| `scripts/build-zip.sh` | 配布用ZIPを作成するビルドスクリプト |

## 配布用ZIPの作り方

「誰でもダウンロードしてすぐ使える」形にするため、拡張機能一式と
インストール手順書をまとめたZIPファイルを作成できます。

```bash
./scripts/build-zip.sh
```

`dist/gemini-image-bulk-downloader-v<バージョン番号>.zip` が生成されます。
このZIPをそのまま配布すれば、受け取った人は中の
`INSTALL_README.txt` の手順（後述のインストール方法と同じ内容）
に従うだけでインストールできます。

ZIPの中身は、フォルダで包まずファイルを直下に配置しています。
Windowsの「すべて展開」はZIP名と同じフォルダを自動作成してから展開する
ため、もしZIP側にも同名の入れ子フォルダが入っていると、展開後に
フォルダが二重になり、Chromeの「拡張機能を読み込む」ダイアログで
manifest.jsonが見つからない、という混乱を招きます。ファイルを直下に
置くことで「展開してできたフォルダ＝そのまま選択するフォルダ」になり、
迷わない構成にしています。

`dist/` はビルド生成物のため `.gitignore` でリポジトリ管理外にしています。
配布のたびに `scripts/build-zip.sh` を実行して作り直してください。

## インストール方法（開発者モードで読み込む）

1. Chromeで `chrome://extensions` を開く
2. 右上の「デベロッパーモード」をオンにする
3. 「パッケージ化されていない拡張機能を読み込む」をクリックし、このプロジェクトのフォルダ（配布用ZIPの場合は展開したフォルダ）を選択する
4. 拡張機能一覧にアイコンが追加されれば完了

※ Chrome Web Store（一般公開ストア）を経由しないインストール方法のため、
Chrome再起動時に「デベロッパーモードの拡張機能が無効になっています」と
いう警告バナーが出ることがあります。「そのまま維持」を選べば引き続き
使用できます。詳しいトラブル対応は `docs/INSTALL_README.txt` を
参照してください。

## 使い方

1. Gemini（https://gemini.google.com/ ）で画像を生成する
2. 拡張機能のアイコンをクリックしてポップアップを開く
3. 「ファイル名の接頭辞」を入力する（未入力の場合は既定値 `gemini_image` が使われる）
4. 「一括ダウンロードを実行」ボタンを押す
5. まずページが自動でスクロールされ、遅延読み込みされる古い画像も読み込まれる
   （ポップアップを開いたままにしておくと、進捗メッセージがリアルタイムで表示される）
6. ページ内の生成画像が `プレフィックス_001.png`、`プレフィックス_002.png`... という
   ファイル名で、既定のダウンロードフォルダに順番に保存される

画像が1枚も見つからなかった場合や、対象がGeminiのページでない場合は、
ポップアップ内にエラーメッセージが表示されます。
また、画像の枚数が多い場合、Chromeから「複数ファイルのダウンロード」の
許可を求めるダイアログが表示されることがあります。その場合は「許可」を
選択してください（ポップアップ内にもその旨の案内を表示しています）。

## 注意事項

GeminiのHTML構造（クラス名など）はGoogle側の仕様変更で変わることがあります。
特定のクラス名に依存すると変更にすぐ弱くなるため、`content.js` の画像抽出処理は
次のような汎用的な方針で作っています。

1. ページ内の全`<img>`要素を対象にする（Shadow DOM の中まで再帰的にたどる。
   GeminiのようなWeb Componentsベースのアプリでは、画像が通常の
   `document.querySelectorAll` からは見えないShadow DOM内に描画されている
   ことがあるため）
2. 集めた`<img>`から、以下の条件に当てはまるものを「生成画像ではない」と
   みなして除外する
   - `<nav>` / `<button>` / 入力欄など、UI装飾の中にある画像
   - 幅・高さが128px未満の小さい画像（アイコン類）
   - `.svg`（AIが生成する写真・イラストは通常SVGではないため）
   - ファイル名に `avatar` `logo` `favicon` `profile` `sparkle`（Geminiの
     キラキラロゴ）`spinner` を含むもの
3. 残った画像のURLが `blob:` 形式（ページ内で一時的に作られたURL）の場合は、
   `background.js`（ダウンロードを実行する別のスクリプト）からは直接
   アクセスできないため、`content.js`側で先にデータを読み込み、
   `data:` URL（画像データを直接埋め込んだ文字列）に変換してから渡す

それでもうまく画像を抽出できなくなった場合は、Chromeの検証ツール(F12)で
実際の`<img>`タグの様子（クラス名・属性・Shadow DOMの有無など）を確認し、
`content.js` の `extractGeminiImageUrls` 関数内のフィルタ条件を調整して
ください。
