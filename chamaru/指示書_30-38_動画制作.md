### 絶対に守ること（先に読む）

1. **茶丸は生成しない。** 切り抜き済みの透過PNGを毎回合成する。Geminiで生成するとキャラがドリフトする
2. **背景プロンプトから「中央手前を空ける」指定を消さない。** 茶丸を置く場所
3. **光は全カット左固定。** 茶丸の透過PNGが左採光で作られているため、右から光を当てると陰影が破綻する
4. **茶丸のピクセルは加工しない。** 背景・光・文字だけ処理する
5. `workshop` など開いた語を背景プロンプトに使わない（洋風の工房が出て世界観が壊れる）
6. **虫の音を入れない。** 全9本のExcludeに `crickets, insects` が入っている（後述）
7. **画面疲れ（33・37）に紅葉を入れない。** Geminiプロンプトの `with no autumn colour` を消さない（後述）
8. **40Hz重ね（34のみ）は音量統一の前**に行う
9. **35（目覚め）は音声を通しでループしない**
10. **効能を断定しない。** 「改善する / 解消する / 治る / 効く / クリアになる」は全部NG

## 2. ⚠️ 10月固有のルール（3つ）

### ルール1：虫の音を入れない

10月中旬で虫はほぼ鳴き終わる。だが**Sunoは "autumn" から虫の音を出しやすい**ので、明示的に除外しないと9月分と同じ音になる。

> **全9本のExcludeに `crickets, insects` が入っている。消さないこと。**

### ルール2：画面疲れ（33・37）は紅葉を使わない

紅葉は赤・橙の**高彩度**。画面疲れの要件は「暗め・低彩度・光源弱め」で、**目を休めることが目的**。年間で最も鮮やかな色を、最も刺激を減らしたい回に使うのは矛盾する。

33・37は**苔・常緑（竹・杉）・灰色の石・雨**の低彩度で作る。

> **Geminiプロンプトの `with no autumn colour — only deep greens and greys` を必ず残す。**
> 消すとGeminiが季節から紅葉を推測して勝手に入れてくる。

### ルール3：鹿威し（ししおどし）は使う状態を選ぶ

**まだ一度も使っていない和の音。** 「カーン」という断続音なので、均一密度が必要な集中・ブレインフォグには**使えない**。余白の多い**31（安眠）と32（リセット）だけ**で使う。

Sunoは `shishi-odoshi` を理解しない可能性があるため、**`bamboo water fountain` を併記**している。

## 5. Step 2 — 4バリエーションの分析

Sunoの4曲をそのまま使わず、**分析して狙った曲調になるよう組み合わせる**のがこのチャンネルの手法。

### 計算する指標

Python（numpy + soundfile）で書く。

| 指標 | 定義 |
|---|---|
| **t1 / t2 / t3** | 10秒窓のRMS(dB)を計算し、曲全体を3等分してそれぞれの平均 |
| **rng** | RMS(dB)系列の 95パーセンタイル − 5パーセンタイル（小さいほど平坦） |
| **hf_ratio** | 2000Hz以上のFFTエネルギー比率（**33・37で使う**） |

```python
# 10秒窓・ホップ10秒（重なりなし）でRMSを算出し dB に変換
# rms_db = 20 * log10(rms + 1e-12)
# t1,t2,t3 = 系列を3等分した各区間の平均
# rng = np.percentile(rms_db, 95) - np.percentile(rms_db, 5)
```

### 実績値の目安（過去52本の分析より）

- **t1**: -16〜-12dB程度
- **rng**: 平坦なもので4〜6dB、起伏があるもので8〜12dB
- **hf_ratio**: 低いもので0.02程度、高いもので0.10程度

この範囲から大きく外れる曲は、Sunoの生成が指示から逸れている可能性が高い。

**結果はJSONに保存する**（11月分と同じ基準で比較するため）。

## 6. Step 3 — 状態別の選定・組み立て

**状態ごとにロジックが違う。ここを間違えると設計が壊れる。**

### つなぎ方の共通ルール

- **異なる曲同士のクロスフェード：8秒**
- **ループの継ぎ目：6秒**（線形クロスフェード）
- Sunoの4テイクは音量がばらつくことがある。**組み立て前にRMSを揃えておく**と継ぎ目に段差が出ない

---

### 30・36 ｜ 集中 — rng最小順に4曲すべて

1. 4曲を分析
2. **rngが小さい順に4曲すべて**採用
3. その順に並べて**8秒クロスフェード**で連結
4. **6秒継ぎ目でループ**して**ちょうど3600秒（60分）**にする

---

### 32 ｜ リセット — 集中と同じ

1. rng最小順に4曲すべて採用
2. 8秒クロスフェードで連結 → 6秒継ぎ目でループ
3. **ちょうど5400秒（90分）**にする

---

### 31・38 ｜ 安眠 — 終盤が静かな曲を最後に

1. 4曲を分析
2. **t3が最も小さい曲（＝終盤が最も静かな曲）を最後に配置**する
3. 残り3曲は任意の順で前に置き、8秒クロスフェードで連結
4. 6秒継ぎ目でループして**ちょうど5400秒（90分）**にする

> 起伏はあってよいが、**締めが静かになること**が要件。

---

### 34 ｜ ブレインフォグ — rng最小の2曲のみ

1. 4曲を分析
2. **rngが小さい順に2曲だけ**採用（均一密度を最優先。40Hzを重ねる下地として重要）
3. 2曲を8秒クロスフェードで連結 → これを1ユニットとする
4. 6秒継ぎ目でループして**ちょうど3600秒（60分）**にする

---

### 33・37 ｜ 画面疲れ — hf_ratio最小の2曲のみ

1. 4曲を分析
2. **hf_ratioが小さい順に2曲だけ**採用（高域が少ない曲）
3. 2曲を8秒クロスフェードで連結 → 6秒継ぎ目でループして**ちょうど3600秒（60分）**
4. **仕上げに6.5kHz程度のローパスを軽くかける**

---

### 35 ｜ 目覚め — 2曲のみ・通しループ禁止

1. 4曲を分析
2. **t1が最小の曲**（＝いちばん静かに始まる曲）を「前半用」に選ぶ
3. **t3が最大の曲**（＝いちばん明るく終わる曲）を「後半用」に選ぶ
4. 前半用を**6秒継ぎ目でループ**して `1800 − len(後半用) − 8` 秒ぶん作る
5. 前半用の末尾と後半用を**8秒クロスフェード**で接続
6. **合計をちょうど1800秒（30分）にする**

```
[前半用をループ（約26分）] --8秒CF--> [後半用を1回だけ（約4分）] = 1800秒
```

> ⚠️ **全体を通しでループしない。** 「静か→やや明るい」の一方向の設計を壊すため。
> ⚠️ 後半用は**1回だけ**。繰り返さない。

## 7. Step 4 — 40Hzバイノーラル重ね（34のみ）

**Sunoでは作れない。** バイノーラルビートは左右の周波数差で成立するため、生成AIでは精度が出ない。ffmpegで後付けする。

**検証済み**（L=200Hz / R=240Hz → 差分40Hz をFFTで実測確認）。

```bash
ffmpeg -y -i input.wav \
  -f lavfi -i "sine=frequency=200:sample_rate=48000" \
  -f lavfi -i "sine=frequency=240:sample_rate=48000" \
  -filter_complex "\
[0:a]aresample=48000,pan=mono|c0=c0[ml];\
[0:a]aresample=48000,pan=mono|c0=c1[mr];\
[1:a]volume=0.05[tl];[2:a]volume=0.05[tr];\
[ml][tl]amix=inputs=2:duration=first:weights=1 1,volume=2[L];\
[mr][tr]amix=inputs=2:duration=first:weights=1 1,volume=2[R];\
[L][R]join=inputs=2:channel_layout=stereo[out]" \
  -map "[out]" -c:a pcm_s16le out.wav
```

### ハマりどころ

**`amix` でいきなり混ぜるとステレオがダウンミックスされ、左右分離が壊れる。**
上記のように **左右チャンネルを個別に分解 → 個別に混ぜる → 最後に `join` で戻す** のが正解。

- トーン音量は `0.05`（かなり小さい）。上げすぎると音楽を邪魔する
- **必ず Step 5（音量統一）の前**に実行
- 処理後、FFTで L=200Hz / R=240Hz が分離していることを確認する

## 11. Step 8 — 動画化

### 尺ごとのパラメータ（3種類あるので注意）

| 尺 | 該当 | `-t` | zoompan `d=` | zoompan `z=zoom+` | `afade` out `st=` | `-stream_loop` |
|---|---|---|---|---|---|---|
| **30分** | 35 | 1800 | 43200 | 0.0000018519 | 1785 | **なし** |
| **60分** | 30・33・34・36・37 | 3600 | 86400 | 0.00000092593 | 3585 | あり |
| **90分** | 31・32・38 | 5400 | 129600 | 0.00000061728 | 5385 | あり |

> ⚠️ **35（目覚め）では `-stream_loop -1` を付けない。** 音声を無限ループさせると一方向の設計が壊れる。35の音源は Step 3 でちょうど1800秒に作ってある。
> ⚠️ `zoompan` の増分は「8%ズームを尺いっぱいで使い切る」値（0.08 ÷ フレーム数）。**尺が変わったら必ず計算し直す。**

### 60分の例

```bash
ffmpeg -i bg_with_chamaru.png -stream_loop -1 -i audio.wav -t 3600 \
  -vf "crop=2731:1536,zoompan=z=zoom+0.00000092593:d=86400:x=iw/2-(iw/zoom/2):y=ih/2-(ih/zoom/2):s=1920x1080:fps=24,format=yuv420p" \
  -r 24 -map 0:v:0 -map 1:a:0 -c:v libx264 -preset veryfast -crf 21 -pix_fmt yuv420p \
  -c:a aac -b:a 192k -af "afade=t=in:st=0:d=3,afade=t=out:st=3585:d=15" -movflags +faststart out.mp4
```

### 30分（35）の例 — `-stream_loop` なし

```bash
ffmpeg -i bg_with_chamaru.png -i audio.wav -t 1800 \
  -vf "crop=2731:1536,zoompan=z=zoom+0.0000018519:d=43200:x=iw/2-(iw/zoom/2):y=ih/2-(ih/zoom/2):s=1920x1080:fps=24,format=yuv420p" \
  -r 24 -map 0:v:0 -map 1:a:0 -c:v libx264 -preset veryfast -crf 21 -pix_fmt yuv420p \
  -c:a aac -b:a 192k -af "afade=t=in:st=0:d=3,afade=t=out:st=1785:d=15" -movflags +faststart out.mp4
```

### 音声だけ差し替える場合

```bash
ffmpeg -i old.mp4 -i new_audio.wav -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -b:a 192k out.mp4
```

## 14. 遵守事項

### 薬機法（医薬品医療機器等法）

| NG | OK |
|---|---|
| 改善する / 解消する / 治る / 効く / クリアになる | 〜の時に / 〜のための / 〜に寄り添う（状態・行為表現） |
| 40Hzで脳がクリアになります | 40Hz帯の低い持続音を重ねた設計です |

**英語も同じ考え方**

| NG | OK |
|---|---|
| Cure / Heal / Fix / Clears brain fog | **For** foggy mornings / **When** your head feels heavy |
| Boosts focus / Improves concentration | **For** quiet focus / **Designed for** long work sessions |
| Calm Your Nervous System / Reduce Stress | **When** the day has been too much |

- **`ガンマ波` / `gamma wave` / `nervous system` はタグにも入れない**
- 「ブレインフォグ」はタイトルに常用せず、説明文とタグに置く（月1〜2本の専用回でのみ正面から使う）

### YouTube（量産型コンテンツ対策）

- AI開示を必ず設定（未設定は警告 → 収益停止 → YPP除外の対象）
- 同じ曲のピッチ/速度違いはNG。毎回本当に別の曲を作る
- 説明文は毎回書き下ろす（署名ブロック以外は使い回さない）
- 同型を一気に大量投稿しない。判定はチャンネル単位

> 10月は**週2本**に落としている（9月までは週3本）。ペースを守ること。
