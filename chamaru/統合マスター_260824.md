## ローカライズ（日英の出し分け）

**本書はタイトル・概要を日英で分離して記載している。** YouTubeは言語ごとにタイトル・説明文を出し分けられるため、1本のタイトルに日英を併記する必要はない。併記をやめると**それぞれ100文字をフルに使える**。

### 設定手順

1. YouTube Studio → 左メニュー **「字幕」**
2. 対象動画を選択 → **元の言語（日本語）を設定**して「確認」
   - ここが前提条件。元の言語が未設定だと翻訳を追加できない
3. **「言語を追加」** → 英語
4. 英語の行の **「タイトルと説明」→「追加」**
5. 左に日本語原文が出るので、右に英語版を入力 → **「公開」**

### チャンネル自体の翻訳

YouTube Studio →「カスタマイズ」→「基本情報」→「チャンネル名と説明の翻訳」→「＋言語を追加」

> 英語のサムネ・タイトルで流入させても、チャンネルが日本語だけだと離脱する。動画のローカライズとセットで設定すること。

### 切り替わる条件

視聴者の**国や地域ではなく、YouTubeのアプリ／ブラウザの言語設定**で決まる。検証は自分のYouTube言語設定を英語に切り替えて確認する。

### ローカライズできないもの

| 項目 | 可否 |
|---|---|
| タイトル | ✅ |
| 説明文 | ✅ |
| **タグ** | ❌ 全言語共通で1セット |
| **サムネイル** | ❌ 1枚で両言語に対応させる必要がある |

## タグ設計ルール

**共通2 ＋ 状態別3〜4 ＋ 個別5〜6** の3層で組む。10〜12語。500文字上限に対して十分余裕がある。

### ① 共通（全話）
```
和風BGM, japanese ambient
```

### ② 状態別（固定）

| 状態 | 日本語 | 英語 |
|---|---|---|
| 集中 | 作業用BGM, 集中BGM, 勉強用BGM／仕事用BGM | study music, focus music／work music |
| リセット | 休息BGM, リラックスBGM, 切り替え | relaxing music |
| 安眠 | 睡眠用BGM, 安眠BGM, 寝る前BGM, 入眠 | sleep music, night ambient |
| 目覚め | モーニングBGM, 目覚め, 朝活 | morning music, wake up music, gentle morning |
| ブレインフォグ | ブレインフォグ, 40Hz, バイノーラルビート | brain fog, binaural beats, 40hz binaural |
| 画面疲れ | 休息BGM, デジタルデトックス, 目の休息 | screen break, digital detox, eye rest |

### ③ 個別（可変）
主役楽器 ＋ 自然音 ＋ 季節（`夏BGM` / `初秋`）を、**その回に実際に入っている音だけ**書く。

### 禁止事項
- **他状態のタグを混ぜない**（例：リセット回に `作業用BGM`）。状態別の流入データが判別できなくなる
- **`BGM` 単体・`癒し` 単体などの汎用語を入れない**（ハッシュタグ側には残してよい）
- **指示文をタグにしない**（例：`headphones recommended`）
- **入っていない楽器・音を書かない**

### `ガンマ波` / `gamma wave` は使わない

`40Hz`（周波数の事実表記）と違い、脳への作用を含意する語。薬機法ルールに照らしてグレーなため、英語圏で一般的なタグだが採用しない。

## サムネイル設計

**現在2形式が混在している。** 26〜29から新形式（バッジ形式）に移行した。

### 01〜25：3行構成（`make_thumb.py` 形式）

```
タイトル（大）    例: 集中
時間帯・尺（中）  例: 朝の茶室で 60分
ジャンル・季節（小）例: 静かな和のBGM ‑ 青竹
```

### 26〜29：バッジ形式

**主ラベル（大・日本語）＋ 区切り線 ＋ バッジ ＋ 右下ロゴ**

| # | 主ラベル | バッジ |
|---|---|---|
| 26 | `目覚め` | `30 MIN` |
| 27 | `目覚め` | `30 MIN` |
| 28 | `頭のもや` | `40Hz` / `60 MIN` |
| 29 | `40Hz` | `頭のもや` / `60 MIN` |

- 主ラベルは**日本語**（当初英語で設計したが日本語に変更）
- **季節の落款（朱色の「夏」印）は不採用**。現在はシンプル構成
- 数値バッジ（`30 MIN` `40Hz`）は数字なので日英どちらの視聴者にも読める

### 28・29 でA/Bテストを実施中

**28＝状態名主体（頭のもや）／ 29＝周波数主体（40Hz）。**
「状態名で引くか、周波数で引くか」の検証。**この2本のラベル設計は変更しないこと。**

26・27は逆に**サムネを統一**している（新状態のシリーズ認識を優先。ここでA/Bを重ねると変数が2つになり結果が読めなくなる）。

> **`頭のもや` という表記について**：カタカナの「ブレインフォグ」を避けた平易な日本語。日本語圏では「ブレインフォグ」の認知度がまだ低く、また症状名を前面に出すより薬機法的にも安全側。タグ・ハッシュタグは検索語として `ブレインフォグ` を維持し、**サムネは理解しやすさを優先**という使い分けになっている。

### 茶丸の配置座標

**サムネイル（01〜29 共通）**
```
SUBJECT_CX = 285
BASE_Y     = 672
SUBJECT_H  = 430
```
> テキストレイアウトが3行構成→バッジ形式に変わっても、**茶丸の位置は全話統一**。チャンネル一覧でのシリーズ感が保たれる。

**動画背景（話ごとに手動調整）**

Geminiの出力構図が毎回違うため、話ごとに調整が必要。26〜29の実績値：

| # | cx | basey | th |
|---|---|---|---|
| 26 | 1500 | 1180 | — |
| 27 | 1300 | 1270 | — |
| 28 | 1350 | 1480 | 520 |
| 29 | 1550 | 1350 | 540 |

### 必ず確認すること

**完成したサムネを 246×138 px に縮小して確認する。** これがモバイルフィードでの実サイズ。この状態で `40Hz` `30 MIN` が読めなければ、文字サイズかコントラストを調整する。

# プレイリスト設計

**状態ごとに1つ、計6つ。** 2026-08-22時点で**5つ作成済み・並び順確認済み**（集中・リセット・安眠・目覚め・頭のもや）。画面疲れは対象動画が3本揃う10/26以降に作成する。

## なぜ最優先なのか

8月時点の実績は **インプレッション93 / 視聴11回**。29本を1ヶ月投稿してこの数字ということは、**YouTubeがこのチャンネルをほぼ誰にも見せていない**という状態。

一方で視聴維持率は良い（完走100%の回もある）。**ボトルネックは品質ではなく「表示されていない」こと。**

プレイリストは制作コストゼロで、いま最も効くはずの施策。

- **プレイリスト自体が検索結果に独立して表示される**
- 自動再生で視聴が連鎖し、**セッション時間**が伸びる（YouTubeが最も重視する指標のひとつ）
- **「状態で選ぶ」というチャンネルの設計そのものを形にできる**

## 作成手順（YouTube Studio）

1. YouTube Studio → 左メニュー **「コンテンツ」** → **「再生リスト」** タブ
2. **「新しい再生リスト」**
3. タイトルを入力 → 公開設定を **「公開」** に
4. 作成後、鉛筆アイコンから説明文を入力
5. 動画を追加（下記の収録リストの順に）
6. **並び順を「手動」に設定する** ← 自動並び替えのままだと意図した順序が保たれない

> ⚠️ **並べ替えのコツ**：YouTube Studioの再生リスト編集ページ（`studio.youtube.com/playlist/<id>/videos`）にはドラッグ並べ替え機能がない。ページ右上の**「YouTube で編集」**から実際の`youtube.com/playlist?list=<id>`側を開くと「手動設定」ドロップダウンとドラッグハンドル（≡）が使え、そちらで並べ替える。

## 収録順について

**季節順（夏 → 初秋 → 紅葉）に並べる。** シリーズとして辿れるようにするため。

> ⚠️ **目覚め・ブレインフォグは通し番号順＝季節順にならない。** 26〜29は9月分（13〜25）の後に制作したが季節は夏に戻るため。下記の収録リストの順に従うこと。

後から視聴維持率を見て、**最も完走率の高い動画を先頭に移す**という運用に切り替えてもよい（「すべて再生」で最初に流れるのがその動画になるため）。ただし現時点ではデータが薄すぎて判断できない。

## プレイリスト運用ルール

### 新作を出したら必ず追加する

**投稿と同時にプレイリストへ入れる。** 忘れると自動再生の連鎖から漏れる。

10月の追加先：

| 公開日 | # | 追加先プレイリスト |
|---|---|---|

| 10/30 | 38 | 安眠 |

### 説明文の表現ルールは動画と同じ

- **効能の断定はしない**（改善する / 解消する / 治る / 効く / クリアになる はNG）
- **40Hzは「音の設計」として書く。効果として書かない**
- 英語も同様（Cure / Heal / Boosts / Calm Your Nervous System はNG。For / When で書く）

### 効果の確認方法

YouTube Studio → アナリティクス → **リーチ** → **トラフィックソース** で「再生リスト」からの流入が見られる。

また **「視聴者維持率」→「セッション時間」** の変化にも注目する。プレイリストが機能していれば、1回の訪問で複数動画が再生されるようになる。

**1ヶ月は様子を見る。** 数字が動かなくても、プレイリスト自体が検索インデックスに載るまで時間がかかる。

### この4本の狙い

9月分（15・21＝目覚め／17・23＝ブレインフォグ）と**季節の固有性で明確に差別化する**。

**目覚め — 「蝉が鳴き出す前」**
夏の明け方には固有性がある。日の出が4時半頃と早く、**蝉が鳴き出す前の30〜60分だけ、真夏なのに静かで涼しい**。一日で唯一涼しい時間帯という実用的な訴求も立つ。9月版（朝露・すすき）とコンセプトが正面から被らない。

**ブレインフォグ — 夏の自然音は40Hzの下地として理想的**
- 実需が明確：「暑さで思考がまとまらない午後」
- **技術的な利点**：蝉の遠音・水音は広帯域の持続音なので、**40Hzトーン（volume 0.05）が自然に溶ける**。静寂の多い曲だと小音量でも40Hzが浮いて聴こえる
- **選定ロジックとの相性**：自然音を主体テクスチャにすると rng が構造的に小さくなり、「rng最小の2曲」が機能しやすい

# 付録

## 制作フロー

1. Suno生成 → WAV保存（1プロンプトから4曲出る）
2. **4バリエーションの分析**（t1/t2/t3・rng・必要なら hf_ratio）
3. **状態別の選定・組み立て**（下記）→ 目標尺ちょうどのWAVにする
4. **（ブレインフォグのみ）40Hz重ね** ← 音量統一の**前**
5. 音量統一 -20dBFS（`normalize_all.py`。ピーク-1.5dBキャップ、可逆ゲインのみ）
6. Gemini で背景生成 → ✦透かし除去 → 茶丸の透過PNGを合成（`generic_prep.py`）
7. ffmpeg zoompan 8%スロームズームで動画化
8. サムネ作成

### 尺の対応

| 状態 | 尺 | ffmpeg `-t` | zoompan `d=` | zoompan `z=zoom+` | `afade` out `st=` | `-stream_loop` |
|---|---|---|---|---|---|---|
| 目覚め | 30分 | 1800 | 43200 | 0.0000018519 | 1785 | **なし** |
| 集中 / ブレインフォグ / 画面疲れ | 60分 | 3600 | 86400 | 0.00000092593 | 3585 | あり |
| リセット / 安眠 | 90分 | 5400 | 129600 | 0.00000061728 | 5385 | あり |

> ⚠️ **目覚め回では `-stream_loop -1` を付けない。** 音声を無限ループさせると一方向の設計が壊れる。目覚めの音源は最初からちょうど尺で作る。
> ⚠️ `zoompan` の増分は「8%ズームを尺いっぱいで使い切る」値（0.08 ÷ フレーム数）。尺が半分なら増分は倍になる。

## Suno 4バリエーションの組み合わせ手法

Sunoは1プロンプトから4曲（main, _1, _2, _3）出る。1曲をループするのではなく、4曲を分析して狙った曲調になるよう組み合わせる。

### 分析する指標

| 指標 | 定義 |
|---|---|
| **t1 / t2 / t3** | 10秒窓のRMS(dB)を計算し、曲全体を3等分してそれぞれの平均 |
| **rng** | RMS(dB)系列の 95パーセンタイル − 5パーセンタイル（小さいほど平坦） |
| **hf_ratio** | 2000Hz以上のFFTエネルギー比率（画面疲れ用） |

### 状態ごとの選定ロジック

| 状態 | ロジック |
|---|---|
| 集中・リセット | rng最小（最も平坦）順に**4曲すべて**採用、順に並べてクロスフェード連結 |
| 安眠 | **終盤(t3)が最も静かになる曲を最後に**配置 |
| 目覚め | **2曲のみ**。t1最小の曲を前半にループ、t3最大の曲を後半に**1回だけ**繋げる。**全体を通しでループしない** |
| ブレインフォグ | rng最小の**2曲のみ**（均一密度を最優先。40Hzを重ねる下地として重要） |
| 画面疲れ | hf_ratio最小の**2曲のみ**＋6.5kHz程度のローパスを軽くかける |

### つなぎ方

- 異なる曲同士のクロスフェード：**8秒**
- ループの継ぎ目：**6秒**
- 目標尺まで届かない場合は、継ぎ目を作ってから通し全体をループ延長
- Sunoの4テイクは音量がばらつくことがある。組み立て前にRMSを揃えておくと継ぎ目に段差が出ない

### 実績値の目安（9月13話・52本の分析より）

- **前半t1**: -16〜-12dB程度
- **rng**: 平坦なもので4〜6dB、起伏があるもので8〜12dB
- **hf_ratio**: 低いもので0.02程度、高いもので0.10程度

## 40Hz バイノーラルの重ね方（17・23・28・29）

**Sunoでは作れない。** バイノーラルビートは左右の周波数差で成立するため、生成AIでは精度が出ない。ffmpegで後付けする。検証済み（L=200Hz / R=240Hz → 差分40Hz をFFTで実測確認）。

```bash
ffmpeg -y -i suno.wav \
  -f lavfi -i "sine=frequency=200:sample_rate=48000" \
  -f lavfi -i "sine=frequency=240:sample_rate=48000" \
  -filter_complex "\
[0:a]aresample=48000,pan=mono|c0=c0[ml];\
[0:a]aresample=48000,pan=mono|c0=c1[mr];\
[1:a]volume=0.05[tl];[2:a]volume=0.05[tr];\
[ml][tl]amix=inputs=2:duration=first:weights=1 1,volume=2[L];\
[mr][tr]amix=inputs=2:duration=first:weights=1 1,volume=2[R];\
[L][R]join=inputs=2:channel_layout=stereo[out]" \
  -map "[out]" -c:a pcm_s16le out.wav
```

**ハマりどころ**：`amix` でいきなり混ぜると**ステレオがダウンミックスされ左右分離が壊れる**。左右チャンネルを個別に分解 → 個別に混ぜる → 最後に `join` で戻すのが正解。

- トーン音量は `0.05`（小さめ）。上げすぎると音楽を邪魔する
- **ヘッドホン推奨を概要欄に明記**（スピーカーでは左右が空中で混ざり構造が成立しない）
- 40Hz重ねは**音量統一（-20dBFS）の前**に行う

> **28・29は自然音（水音・蝉）を主体テクスチャにしているため、広帯域の持続音が40Hzトーンを自然に隠す。** 静寂の多い曲だと `0.05` でも40Hzが浮いて聴こえるが、この2本は下地として理想的。
