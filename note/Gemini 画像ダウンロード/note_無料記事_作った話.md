# タイトル案（3つ）

1. **非エンジニアが「Geminiの画像を1クリックで一括保存するツール」を作ったら、"キラキラマーク"だけ保存されて泣いた話**
2. **Geminiの生成画像、1枚ずつ保存するのをやめたくてChrome拡張を自作した（作る過程で3回ハマった）**
3. **「画像をまとめてダウンロードするだけ」がなぜこんなに難しいのか。拡張機能を作って理由がわかった**

---

# Geminiで画像を作るのは一瞬。でも「保存」で毎回止まる

Geminiで画像を作るようになってから、地味に時間を取られている作業があります。

**できた画像を、パソコンに保存する。** これだけ。

1枚2枚ならいいんです。でも私は、LINEスタンプ用のイラストや、動画のサムネ素材を**まとめて何十枚も**作ります。そうすると——

- 画像を右クリック →「名前を付けて保存」→ ファイル名を打つ → 次の画像へ……
- 保存先はぐちゃぐちゃ、ファイル名は「画像 (1).png」「画像 (2).png」
- どれがどの画像かあとで分からなくなる
- チャットが長くなると、上のほうの画像を探すのも一苦労

「これ、ボタン1つで全部、連番の名前を付けて保存できたらいいのに」

そう思って、ツールを作ることにしました。私はプログラミングができないので、**AI（Claude Code）に相談しながら**です。作るのはChromeの拡張機能。

ここから、完成までに3回ハマります。その記録です。

［ここに画像：課題提起（保存がめんどくさい図）］

# 沼① セレクタは合っているのに、画像が1枚も取れない

最初のバージョンは、思ったより早くできました。「ページの中の画像を集めて、ダウンロードする」——AIも「そんなに難しくない」と言っていました。

ところが、実行しても**「生成された画像が見つかりませんでした」**。

おかしい。開発者ツールで見ると、画像の場所（セレクタ）はちゃんと当たっている。画像のURLも取れている。なのに、そのURLから中身を読もうとすると——**何も起きない。エラーですらない。**

原因を突き止めるのに時間がかかりました。Geminiの生成画像のURLは `blob:` という特殊な形式で、**ブラウザのセキュリティ設定（CSP）で「外部から中身を読み込むこと」がブロックされていた**んです。表示はできるけど、プログラムからは触らせない、という状態。

解決策は、発想を変えることでした。**「URLから読み込む」のをやめて、「すでに画面に表示されている画像を、いったんキャンバスに描き写して、そこから取り出す」**。人間が見えているものは、プログラムからも“描き写せる”。

これで、画像が取れるようになりました。

---

# 沼② 実行したら、Geminiの"キラキラマーク"だけが1枚保存された

画像が取れるようになったので、意気揚々と実行。……**保存されたのは、Geminiのロゴ（あのキラキラしたマーク）1枚だけ**でした。肝心の生成画像3枚は、どこにもない。

調べてわかった原因は、3つ重なっていました。

1. ロゴの画像ファイルが、私が指定した「画像を探す条件」にたまたま引っかかっていた
2. 「アイコンっぽいものは除外する」というフィルタを、ロゴがすり抜けていた
3. ——そして一番効いていたのがこれ。私のプログラムは「**まず条件で探して、0件だったら全体をもう一度スキャンする**」という2段構えにしていました。ロゴが**1件見つかってしまった**せいで、「0件じゃないからOK」と判断されて、本命の全体スキャンが走らなかった

「1件も見つからない」より、「余計なものが1件見つかる」ほうが厄介でした。安全網が働かなくなるからです。

対策として、**最初から常にページ全体をスキャンする**方式に一本化。さらに、`.svg` という拡張子や、`sparkle`（キラキラ）・`spinner`（読み込み中のクルクル）といった名前のファイルを除外リストに追加しました。

---

# 沼③ 保存はできた。でも全部「ダウンロード.png」になる

ようやく生成画像が全部保存できるようになりました。感動……したのも束の間。

**保存されたファイル名が、「ダウンロード.png」「ダウンロード (1).png」「ダウンロード (2).png」。**

このツールの目的は「接頭辞を付けて連番で保存する」ことです（`Route_001.png`、`Route_002.png`…）。ファイル名が付かないなら、**存在意義の半分がない。**

原因は、またしてもブラウザの仕様でした。**Chromeは、キャンバスから取り出した形式の画像に対して、こちらが指定したファイル名を無視することがある**、という既知の挙動。

解決策は、「ダウンロードが始まる直前に横から割り込んで、ファイル名を強制的に上書きする」処理を足すこと。Chromeにそういう仕組みがちゃんと用意されていました。

実機で `Route_001.png` 〜 `Route_006.png` が正しく並んで保存されたときは、素直に嬉しかったです。

---

# （おまけ）動いてからも、人に渡すとまた別の沼がある

自分のパソコンで動いた。じゃあ配布用にまとめよう——ここからも一波乱ありました。

- ZIPにしたら、フォルダが**二重の入れ子**になって「拡張機能を読み込む」画面で認識されない
- 日本語のファイル名を入れたら、Windowsで解凍したときに**文字化け**
- 設定ファイルに1行余計な記述があって**エラーで起動しない**
- 「フォルダを選ぶ画面」でファイルが見えず、操作に迷う（フォルダしか出ない仕様）
- 拡張機能を入れる**前から開いていたタブ**では動かない（タブを再読み込みすれば直る）

これらは1個ずつ潰して、**非エンジニアでも迷わないインストール手順書**を同梱しました。「動くものを作る」と「人が使えるものにする」は、別の作業なんだと痛感しました。

# できたもの

最終的に、こういう拡張機能になりました。

**Geminiのチャット画面で拡張アイコンをクリック → 接頭辞を入力 → ボタン1つ。表示中の生成画像が、チャットを自動スクロールしながら全部回収されて、`接頭辞_001.png` 形式の連番で一括保存されます。**

［ここに動作デモGIF：Gemini画像一括DL_デモ動画.mp4 をGIF化］

- 画像の枚数ぶん、右クリックして名前を打つ作業がゼロに
- 連番なので、あとで並び順が分かる
- チャットのスクロールも自動

# まとめ

「画像をまとめてダウンロードするだけ」が難しいのは、**ブラウザが「表示はさせるけど、プログラムには自由に触らせない」仕組みになっているから**でした。

- 表示できてもURLからは読めない → キャンバスに描き写して取り出す（沼①）
- ロゴが1枚混じるだけで安全網が働かない → 最初から全体スキャンに一本化（沼②）
- ファイル名の指定が無視される → 直前で強制上書き（沼③）

この3つ（＋配布のおまけ）を1個ずつ潰していった結果、Geminiの画像整理が一瞬で終わるツールができました。

コードは読めないままです。やったことは、**「困っていること」をそのままAIに伝えて、出てきたものを試して、ダメだった理由をまた伝える**——これのくり返しだけです。
